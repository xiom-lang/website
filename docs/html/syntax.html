Syntax Reference

Syntax Reference

Variables


"kw">let x: "ty">Int = 42           "cm">// immutable binding
"kw">var y: "ty">Float64 = 3.14     "cm">// mutable binding
"kw">let name = "AXIOM"        "cm">// "kw">type inferred "kw">as "ty">Str
"kw">let v = [1, 2, 3]         "cm">// "kw">type inferred "kw">as "ty">Vec["ty">Int]
"kw">let t = (1, "kw">true)         "cm">// "kw">type inferred "kw">as ("ty">Int, "ty">Bool)
  • let — immutable binding. Cannot be reassigned.
  • var — mutable binding. Can be reassigned with =.
  • Type annotations are optional when the compiler can infer the type.
  • Type inference does not cross function boundaries.

Functions


"kw">fn add(a: "ty">Int, b: "ty">Int) -> "ty">Int {
  "kw">return a + b
}

"cm">// Void "kw">return (no "kw">return "kw">type annotation)
"kw">fn log(message: "ty">Str) {
  io.print(message)
}

"cm">// With contracts
"kw">fn divide(a: "ty">Float64, b: "ty">Float64) -> "ty">Float64
  "kw">requires: b != 0.0
  "kw">ensures:  "kw">result * b == a
{
  "kw">return a / b
}
  • Function signatures are always fully annotated.
  • Contracts (requires, ensures) appear between the signature and the body.
  • The last expression in a block is the return value (tail expression).
  • Every statement must end with ;. Tail expressions do not.

Methods


"kw">pub "kw">type "ty">Vec3 = { x: "ty">Float32; y: "ty">Float32; z: "ty">Float32; }

"cm">// "kw">self "kw">is implicit — fields accessed directly
"kw">pub "kw">fn "ty">Vec3.dot(other: &"ty">Vec3) -> "ty">Float32 {
  "kw">return x * other.x + y * other.y + z * other.z
}

"kw">pub "kw">fn "ty">Vec3.set_x(value: "ty">Float32) {
  x = value   "cm">// "kw">self "kw">is &mut "ty">Vec3 — mutation detected
}
  • Methods use TypeName.methodName syntax.
  • self is synthesized implicitly by the compiler.
  • The compiler infers &Self vs &mut Self from the method body.
  • If a field is mutated anywhere, the receiver is &mut Self.

  "kw">return 1

"kw">for item "kw">in items {

Match


"kw">match value {
  "kw">Some(v) => process(v),
  "kw">None    => handle_absent(),
}

"kw">match state {
  AgentState.Idle              => wait(),
  AgentState.Patrolling(route) => follow(route),
  AgentState.Attacking(target) => engage(target),
  AgentState.Dead(cause)       => log(cause),
}
  • Every match must cover all cases. Non-exhaustive matches are compile errors.
  • Use _ as a wildcard to cover remaining cases.
  • Match arms can be blocks or expressions.
