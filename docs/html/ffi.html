C FFI (Foreign Function Interface)

C FFI (Foreign Function Interface)

AXIOM has zero-cost C interoperability. C functions and types are declared in extern blocks. The compiler generates no wrapper code. C ABI calling conventions are used directly.

unsafe is required because the compiler cannot verify C memory safety.

Extern Blocks


"kw">extern "C" {
  "kw">fn malloc(size: "ty">UInt) -> *"ty">UInt8
  "kw">fn free(ptr: *"ty">UInt8)
  "kw">fn strlen(s: *"ty">UInt8) -> "ty">UInt
  "kw">fn printf(format: *"ty">UInt8, ...) -> "ty">Int32
}

Calling C Functions


"kw">fn c_string_length(ptr: *"ty">UInt8) -> "ty">UInt {
  "kw">unsafe { "kw">return strlen(ptr) }
}

"kw">fn allocate_buffer(size: "ty">UInt) -> *"ty">UInt8 {
  "kw">unsafe { "kw">return malloc(size) }
}

Raw Pointers

Raw pointers (*T) are only usable inside unsafe blocks. They cannot be dereferenced in safe code.


"kw">unsafe {
  "kw">let raw: *"ty">Int = some_c_function()
  "kw">let value = *raw   "cm">// dereference — programmer guarantees validity
  *raw = 42          "cm">// write through pointer
}

Safe Wrappers

The recommended pattern is to wrap C libraries with safe AXIOM interfaces that add contracts:


"kw">fn safe_alloc(size: "ty">UInt) -> "ty">Option[*"ty">UInt8]
  "kw">requires: size > 0
{
  "kw">unsafe {
    "kw">let ptr = malloc(size)
    "kw">if ptr == null_ptr() {
      "kw">return "kw">None
    }
    "kw">return "kw">Some(ptr)
  }
}

"kw">fn safe_free(ptr: *"ty">UInt8) {
  "kw">unsafe { free(ptr) }
}

C-ABI Export

AXIOM functions can be exported with C ABI for consumption from other languages:


"kw">extern "C" "kw">fn axiom_add(a: "ty">Int32, b: "ty">Int32) -> "ty">Int32 {
  "kw">return a + b
}

This compiles to a standard C-callable symbol that can be linked from Rust, Python, or any language with C FFI.

Strategy

AXIOM does not rewrite C libraries. It wraps them with safe interfaces and contract-verified preconditions:

Library C LOC AXIOM Wrapper LOC
SQLite 150,000 ~200
OpenSSL 500,000 ~300
BLAS 100,000+ ~150

The C library provides battle-tested implementation. The AXIOM wrapper adds contracts and type safety.

FFI Best Practices

  • Always use unsafe blocks — never call C functions outside unsafe { }.
  • Wrap with safe functions — expose a safe AXIOM interface with contracts.
  • Validate at the boundary — check pointer validity, buffer sizes, and nullability.
  • Auto-infer contracts from C headers — planned Phase 3 feature for mechanical binding generation.
