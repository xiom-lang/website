Generics

Generics

Generics are implemented through comptime type parameters. The type parameter is resolved at compile time, producing a monomorphised specialisation. No runtime dispatch, no boxing, no virtual calls unless explicitly requested via interface references.

Basic Generics


"kw">fn max[T: "ty">Comparable](a: T, b: T) -> T {
  "kw">if a > b { "kw">return a }
  "kw">return b
}

"cm">// Call sites — T inferred from arguments
"kw">let m1 = max(10, 20)          "cm">// T = "ty">Int
"kw">let m2 = max(1.5, 2.7)        "cm">// T = "ty">Float64

Inline Type Constraints

Type-level requirements are declared inline with the type parameter. This separates type requirements from value-level preconditions:


"cm">// Single constraint
"kw">fn sort[T: "ty">Ord](items: &mut "ty">Vec[T])

"cm">// Multiple constraints
"kw">fn dedup[T: "ty">Eq + "ty">Hash](items: &mut "ty">Vec[T])

"cm">// Constraint with "kw">interface
"kw">fn process[T: "ty">Comparable + "ty">Display](value: T) -> "ty">Str {
  "kw">return value.to_str()
}

Explicit Type Parameters

If a type parameter appears only in the return type and not in any argument, it must be annotated explicitly at the call site:


"kw">fn parse[T](s: "ty">Str) -> "ty">Result[T, "ty">ParseError] { ... }

"kw">let n = parse["ty">Int]("42")   "cm">// T must be explicit — not inferrable from arguments

Generic Types


"kw">type "ty">Stack[T] = {
  items: "ty">Vec[T];
  capacity: "ty">UInt;
  "kw">invariant: items.len() <= capacity;
}

"kw">type Pair[A, B] = {
  first: A;
  second: B;
} "kw">derive["ty">Eq, "ty">Clone]

Monomorphisation

Generics use two-pass monomorphisation:

  • Pass 1 — Register: The compiler scans for concrete instantiations at call sites and registers them.
  • Pass 2 — Specialize: For each registered instantiation, the compiler emits a specialized version with full type substitution.

"cm">// Source
"kw">fn identity[T](x: T) -> T { "kw">return x }

"kw">let a = identity(42)      "cm">// T = "ty">Int
"kw">let b = identity("hi")    "cm">// T = "ty">Str

"cm">// Generated (conceptual)
"kw">fn identity_Int(x: "ty">Int) -> "ty">Int { "kw">return x }
"kw">fn identity_Str(x: "ty">Str) -> "ty">Str { "kw">return x }

This produces zero-overhead abstractions — generic code compiles to the same machine code as hand-specialized versions.

Interface Satisfaction

Inline constraints are checked at monomorphisation time. If a type parameter T: Ord is declared, the compiler verifies that the concrete type satisfies Ord before specializing:


"kw">type "ty">Score = { value: "ty">Int }

"kw">fn "ty">Score.compare(other: &"ty">Score) -> "ty">Int { ... }
"cm">// "ty">Score now satisfies "ty">Comparable

"kw">let winner = max("ty">Score{ value: 10 }, "ty">Score{ value: 20 })
"cm">// Compiler verifies: "ty">Score satisfies "ty">Comparable ✓
"cm">// Generates: max_Score("ty">Score, "ty">Score) -> "ty">Score

If a type does not satisfy the required interface, the compiler produces a clear error:


error[E0301]: "kw">type does not satisfy "kw">interface
  --> src/main.ax:12:10
   |
12 |   "kw">let s = sort["ty">Point](points)
   |           ^^^^^^^^^ "kw">type `"ty">Point` does not satisfy `"ty">Ord`
   |
   = `sort` "kw">requires `T: "ty">Ord` because it must compare elements.
     Type `"ty">Point` "kw">is missing:  "kw">fn compare(other: &"ty">Point) -> "ty">Int
   = help: add `"kw">derive["ty">Ord]` to the "kw">type definition of `"ty">Point`, or
     implement `"kw">fn "ty">Point.compare(other: &"ty">Point) -> "ty">Int` by hand.

Comptime

comptime marks expressions and blocks to be evaluated at compile time. It is the single mechanism for all metaprogramming — generics, reflection, and specialisation all flow through it.


"kw">let size = "kw">comptime expensive_computation()  "cm">// evaluated once, at compile time
