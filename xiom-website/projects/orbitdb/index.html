OrbitDB

An embedded database engine in pure XIOM: B-tree index, write-ahead log, query engine, transactions and crash recovery, organised as a layered engine on the shared durable-systems substrate. It reuses the ecosystem's core primitives instead of copying them.

OrbitDB is in development. The code is private for now, and there are no downloads yet.

Package: xiom.orbitdb -- the embedded engine, codename Satellite (live on the registry, incubating).
Standalone: Station -- the PostgreSQL-class server tier with standalone releases (pending).

What works today

OrbitDB is pre-alpha. The embedded engine (Satellite) has a durable write-ahead log with fsync at every commit, snapshot and replay recovery, transactions with savepoints and MVCC snapshots, typed rows, a query planner with secondary indexes, and a paged storage layer with a bounded cache. The conformance suite passes 166/166 on Windows and WSL, and crash-recovery tests pass for the block store, transactions and the server tier. A 1,000,000-key soak stays under a 4 GB cap at a 1.83 GB peak with exact sample verification. A server tier (Station) is planned on the same engine: it targets trusted networks and local use, with the ORBITWIRE protocol frozen and crash recovery verified -- graceful shutdown and session-loop hardening are the remaining work.

B-tree index

Insert, search and delete on a flat-array B-tree, churn-proven against a model.

Range queries

Low/high scans, min/max and in-order traversal.

Write-ahead log

Append, replay and truncate; durable segment file.

Crash recovery

Disk WAL and page file with crash-recovery tests for the block store, transactions and the server tier; torn-tail healing.

Query engine

A query path with a planner, secondary indexes, and equality/range filters.

Schema catalog

Schema definitions with validation.

Pages and buffer pool

A paged storage layer with a bounded cache; the v2 byte container is the default (v1 auto-detected, migrates on write).

Tuple codec and CRC32C

Byte-packed records; checksums verified on read.

Conformance suite

166/166 on Windows and WSL.

Transactions

Transactions and savepoints with MVCC snapshot pins.

fsync durability

The standard library fsync and sync-write primitives back the durable log path; commit acks are power-loss honest up to the synced seams, and the hardware power-loss test matrix is the remaining step.

What is next

Two-tier direction: the embedded engine (Satellite) is the release line, with a PostgreSQL-class server tier (Station) planned on the same engine -- never a fork. Station v1 is for trusted networks and local use until TLS support lands. Both are pre-alpha today.

  • Next: hardware power-loss testing and finishing the Station v1 work.
  • Station v1: graceful shutdown and session-loop hardening, then reader snapshots.
  • Public downloads will follow when the repository opens.

Pre-alpha: the engine works, but do not put production data in it yet.
