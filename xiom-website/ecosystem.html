XIOM Ecosystem

All official packages live under the xiom-lang organization. Every package is versioned independently, linked from a single registry file.

Organization Structure

|-- xiom              <- compiler (this repo)
|-- registry          <- packages.json index
|
|-- core/              <- XIOM-native core packages
|   |-- std            <- standard library
|   |-- test           <- contract-aware test runner
|   |-- serialize      <- JSON/binary serialization
|   |-- http           <- HTTP client/server
|   |-- json           <- JSON parsing
|   `-- crypto         <- OpenSSL bindings (FFI)
|
|-- data/              <- data infrastructure

Core Packages

These packages ship with the compiler or are critical infrastructure. Built in XIOM unless marked FFI.

std

Standard library. Core types, collections, I/O, strings, math, FFI helpers. Ships with the compiler.

native

test

Contract-aware test runner. Every stdlib function's contract IS its test. fn test_push_respects_capacity.

native

serialize

derive[Serialize, Deserialize] for JSON, binary, and XIOM wire format.

native

http

HTTP client/server. Client wraps libcurl via FFI. Server is an XIOM-native event loop.

ffi

json

JSON parser and serializer. Contract-verified schema validation.

native

crypto

Safe OpenSSL bindings. requires: key.len() == 32 -- type-checked, not something you hope the caller got right.

ffi

Flagship Projects

XiomDB

An embedded typed database. Schema = XIOM types with invariants. Query = XIOM functions with contracts. No SQL strings. No ORM. No migration files.

  • B-tree storage engine
  • Write-ahead log for durability
  • Contract-verified constraints
  • WASM-deployable embedded mode
  • C-ABI for Rust/Python/Tauri
planned -- Phase 3

XiomVDB

An embedded vector database. Built on XiomDB's storage engine. Contract-verified dimension safety prevents the most common runtime crash in every vector DB client.

  • HNSW ANN index
  • Cosine similarity + dot product
  • Dimension mismatch caught at contract layer
  • Built on XiomDB storage engine
  • C-ABI for Kyberon MNEME integration
planned -- Phase 3

How to Publish a Package

  1. Create a repository under xiom-lang/ on Gitea
  2. Add a package.xi manifest at the project root
  3. Open a PR against xiom-lang/registry adding your package to packages.json
  4. Once merged, xiom get your-package resolves it

The registry is intentionally simple -- one JSON file. No database. No website. No authentication beyond Gitea PRs. Upgrade to a proper registry when the ecosystem reaches 50+ packages.
